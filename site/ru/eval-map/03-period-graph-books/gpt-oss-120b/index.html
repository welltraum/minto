Audit of the “Period Graph Books” memo against the Minto Pyramid Principle

Minto Principle ElementDefect(s) IdentifiedWhy It Violates the PrincipleWhat Must Change
Top‑Down StructureThe memo opens with a narrative description (“Since Period 5…”) rather than a clear, single overarching recommendation or conclusion.Minto requires the first sentence (or paragraph) to state the key message (the answer to the decision‑maker’s question). The current opening leaves the reader guessing what action is being sought.Begin with a concise Executive Summary that states the recommended course (e.g., “We should redesign the graph‑book production process to eliminate duplication, assign end‑to‑end ownership, and automate calculations”). All subsequent sections must support this statement.
Logical Flow (Situation‑Complication‑Question‑Answer)The memo mixes “Production” steps with “Issues” without first establishing the situation (current state) and the complication (why it is problematic).The Situation‑Complication‑Question‑Answer (SCQA) framework is not evident; the reader cannot see the logical progression from “what is happening” to “why it matters” to “what we need to decide.”Re‑order content:
1. Situation – brief factual description of the current process (who does what, how many steps).
2. Complication – enumerate the pain points (duplication, errors, lack of ownership).
3. Question – what should we do?
4. Answer – the recommended solution (streamlining, central control, automation).
MECE GroupingThe “Issues” list mixes different problem types (data duplication, calculation errors, unexplained changes, re‑entry of prior‑period data) without clear grouping. Some items overlap (e.g., “inconsistent data” and “incorrect variable‑cost calculations”).Minto demands that supporting points be Mutually Exclusive and Collectively Exhaustive. Overlapping or redundant bullet points dilute clarity and make it harder to prioritize actions.Re‑group issues into MECE categories, e.g.:
• Process Redundancy – multiple data entries, re‑entry of prior‑period data.
• Data Integrity – inconsistent data, unexplained changes, incorrect calculations.
• Ownership & Control – no end‑to‑end responsibility, fragmented hand‑offs.
Hierarchy of DetailThe “Production” steps are presented as a flat list, then the “Issues” list follows, but there is no hierarchy linking each issue to the specific step that generates it.In a pyramid, each lower‑level point should be a logical sub‑point of a higher‑level heading. Without explicit linkage, the reader cannot see which step causes which problem.For each production step, attach the relevant issue(s) as sub‑bullets, or create a two‑column table mapping Step → Problem. This creates a clear cause‑effect hierarchy.
Clarity of the Call‑to‑ActionThe memo ends with “Could we discuss how best to proceed?” – an open‑ended question that does not specify the decision needed.Minto’s “Answer” should be a concrete recommendation, not a vague invitation to discuss. The decision‑maker needs a clear next step.Replace the open question with a specific Decision Request (e.g., “Approve the formation of a cross‑functional task force to redesign the graph‑book workflow and implement an automated data pipeline by Q3”).
Parallelism & ConsistencyBullet phrasing is inconsistent (some start with verbs, others with nouns; mixed tenses).Parallel structure aids readability and reinforces the hierarchy. Inconsistent phrasing weakens the logical flow.Standardize bullet style (e.g., all start with a verb phrase: “Gather data…”, “Calculate points…”, “Transcribe points…”, “Check data…”).
Length & FocusThe memo includes narrative filler (“the transfer inserted another person…”) that does not directly support the key recommendation.Minto advises brevity; every sentence should serve the top‑down argument. Extraneous context dilutes focus.Trim or relocate background information to an appendix; keep the main memo to the essential argument and supporting facts.
Use of HeadingsOnly “Production,” “Issues,” and “Overall assessment” headings are used, but they do not reflect the SCQA hierarchy and are not ordered logically.Headings should mirror the pyramid levels (Situation, Complication, Question, Answer). Misaligned headings confuse the reader’s mental map.Rename and reorder headings to match the SCQA flow (e.g., “Current Process (Situation)”, “Pain Points (Complication)”, “Decision Needed (Question)”, “Proposed Solution (Answer)”).
Data PresentationThe memo mentions “inconsistent data between periods and regions” but provides no quantitative evidence or examples.Supporting arguments should be backed by concrete data to make the case compelling.Insert a brief data snapshot or a chart (or reference an appendix) that quantifies the error rate or duplication cost.
Audience OrientationThe memo assumes the reader knows the history of the transfer and the names of internal groups (e.g., “Color Graphics”) without explaining their relevance.Minto stresses tailoring the message to the audience’s needs; unnecessary jargon can obscure the argument.Provide a one‑sentence context for each stakeholder group or move detailed background to a footnote.

Summary of Required Changes

  1. Insert a clear executive summary that states the recommended action.
  2. Re‑structure the memo using SCQA (Situation → Complication → Question → Answer).
  3. Group issues into MECE categories and link each to the specific production step that generates it.
  4. Replace the open‑ended discussion request with a concrete decision request.
  5. Standardize bullet phrasing and ensure parallelism.
  6. Trim non‑essential narrative and relocate detailed background to an appendix.
  7. Rename headings to reflect the logical hierarchy and order them accordingly.
  8. Add concise data evidence to substantiate the pain points.
  9. Clarify stakeholder references for the audience’s understanding.

Implementing these changes will align the memo with the Minto Pyramid Principle, making the argument more persuasive, easier to follow, and actionable for senior management.

# Fixture 03: Period Graph Books

**Mode:** `audit`
**Language:** `en`

## Context

Corporate Financial Analysis recently took over production of four monthly
graph books used in presentations to senior management. Management knows that
errors and inconsistencies have appeared and asked for corrective proposals.

## Before

```text
Subject: Period Graph Books

Since Period 5, Financial Analysis has been responsible for producing four
graph-presentation books previously handled by Corporate Planning. This memo
describes issues that appeared after the transfer.

Production

1. Gather data from divisional forms, internal documents, and telephone calls.
2. Calculate graph points manually or on the corporate computer, including
   rolling values for revenue, cost, and percentages.
3. Transcribe the points to input sheets. Analysts update the current period,
   then Color Graphics re-enters the points into its own database and generates
   the graphs.
4. Check the data and calculations.

Issues

The transfer inserted another person into an already fragmented process.
Divisional staff and three corporate departments participate, and the same
information may be entered into computer systems three times.

For one book, divisional data are loaded into a dedicated corporate program,
calculated, transferred to Color Graphics input sheets, entered again, and
returned for updates. Problems include inconsistent data between periods and
regions, incorrect variable-cost calculations, unexplained changes to points
that were previously correct, and prior-period data that must be re-entered.

Overall assessment

Most problems arise from a cumbersome fragmented process. No one controls the
data from beginning to end, responsibility is unclear, and errors can fall
between stages. The production process badly needs streamlining, both for each
book and for common calculations. The current team cannot manage the required
changes as well as ongoing production.

Could we discuss how best to proceed?
```

and explain what must change. Do not rewrite the document.
