**Key Thought**
The promised 10x acceleration is currently unrealized because organizations cling to classical development processes; unlocking value requires treating agents as probabilistic systems that demand research cycles, redefining human roles around control points and feedback, and adopting hypothesis-driven workflows.

**Rests on**

**1. Classical development processes create bottlenecks and traps with agents.**
*   **Claim:** Agile handoffs and Jira-based task management negate speed gains and stall progress when agents are involved.
*   **Evidence:** Individual speed increases (e.g., a developer finishing in two hours, an analyst in thirty minutes) are offset by persistent waiting and handoff times. Filing Jira tickets for agent errors stalls research, as these errors represent data for improvement rather than bugs. Resistance to new tools is high; teams that succeed adopt "Product Engineers" who handle end-to-end development or T-shaped teams of two to three people.

**2. Agent development demands a dual engineering-research approach.**
*   **Claim:** Agents cannot be built by classical roles alone; they require infrastructure engineering and probabilistic research, necessitating role splits and new documentation.
*   **Evidence:** Backend developers waste months building custom frameworks, while NLP engineers get stuck on plumbing tasks. Success requires either a "superhuman" or two distinct roles. Analysts fail using classical methods; the IDEF0 methodology effectively maps agents to business functions to scope and simplify requirements. ML System Design Docs are essential for tracking experiments and hypotheses to align with clients.

**3. Human oversight must shift from code review to boundary management and feedback.**
*   **Claim:** Line-by-line code review is impossible; humans must secure control points, provide external context, and manage agent autonomy.
*   **Evidence:** Code generation is too fast for manual review. Humans must retain control over critical contracts, APIs, and databases. CI/CD reviews should feed feedback directly to coding agents rather than humans. Agents are new actors requiring security measures (e.g., defending against compromised agents or risky MCP servers). Humans act as external feedback sources (like GPS correcting an aircraft) to provide context and correct agent drift.
