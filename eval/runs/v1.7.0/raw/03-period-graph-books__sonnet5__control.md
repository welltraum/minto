# Audit: Period Graph Books Memo

## Governing structure defect
The memo has no governing thought. It opens with a factual statement ("Financial Analysis has been responsible...") rather than the key line that should sit at the pyramid's apex: something like "The graph-book production process is broken and needs to be redesigned by an outside team." Instead the memo makes the reader assemble the point from four sections of narrative. The closing question — "Could we discuss how best to proceed?" — confirms there is no answer being asserted, only material being reported.

## Missing situation–complication–resolution logic
- **Situation**: buried in the first paragraph as a historical note (transfer from Corporate Planning), not framed as the stable starting point.
- **Complication**: never stated as a complication. The reader isn't told "and since then, errors have appeared that concern management" — this is implied contextually rather than asserted as the reason the memo exists.
- **Question the memo should answer**: "What is causing the errors, and what should we do about it?" This question is never made explicit, so the reader can't judge whether the body answers it.
- **Resolution**: absent. "Overall assessment" gestures at a diagnosis (fragmented process, no end-to-end owner) but stops short of a recommendation. It ends in a question instead of an answer.

## Grouping and ordering defects
- Sections are ordered by narrative/chronological sequence (Production → Issues → Overall assessment) rather than by the logical groupings a reader needs (diagnosis → cause → recommendation). This is a describing-order structure standing in for an argument.
- "Production" is a four-step process description with no evaluative point — it's scene-setting that should be subordinate evidence under a diagnostic line, not a co-equal section.
- "Issues" mixes structural problems (three departments, triple entry) with a single book's specific symptoms (inconsistent data, wrong variable-cost calculations, unexplained changes) at the same level, without distinguishing systemic causes from symptoms. These are different logical types and shouldn't be flattened into one list.
- "Overall assessment" contains at least three distinct claims bundled together without hierarchy: (1) process is fragmented, (2) no one owns it end-to-end, (3) current team lacks capacity to both fix and run production. Each is a different-level idea; as written they read as an unordered list rather than a summarized, ranked argument (MECE grouping is not attempted).

## Introduction defects
There is no true introduction. Minto's S-C-Q shape requires the opening to orient the reader before detail — instead the memo drops straight into "Since Period 5..." background, which functions as narrative history, not as a scaffold for what follows.

## Key line / support defect
No key line summarizes the supporting sections. A reader skimming only section headers ("Production," "Issues," "Overall assessment") gets no argument — only topic labels. Each section should instead be phrased as a point (e.g., "The process fragments accountability across three departments," "The current team cannot both fix and run production") so the headers themselves carry the pyramid's logic downward.

## What must change
1. State the governing thought up front: diagnosis of root cause plus the action being requested (likely: assign a dedicated team/owner to redesign the process, separate from ongoing production staff).
2. Convert the closing question into an explicit recommendation or decision request tied to that governing thought.
3. Recast section headers as assertions, not topics.
4. Separate systemic causes (fragmentation, unclear ownership, triple data entry) from symptomatic evidence (specific errors in the one book), and subordinate the evidence under the relevant cause.
5. Cut or demote the four-step production narrative to supporting detail under whichever point it substantiates, rather than treating it as an independent section.
