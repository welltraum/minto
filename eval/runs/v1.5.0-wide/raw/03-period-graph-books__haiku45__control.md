# Audit: Period Graph Books Against Minto Pyramid Principle

## Defects Identified

**1. Inverted Structure (Critical)**
The document follows a bottom-up logic: process description → issues → assessment. Minto requires top-down structure: main message → supporting arguments → details. The conclusion (process needs streamlining; team cannot manage changes) appears only in the final paragraph instead of opening the document.

**2. Missing Top-Line Message**
No single, clear statement of the main point appears in the opening. The reader must infer the recommendation from scattered content. The memo ends with "Could we discuss how best to proceed?" rather than stating what should happen.

**3. Process Description Masquerades as Argument**
The "Production" section (four numbered steps) describes the current workflow but makes no argument. This is background detail that belongs in supporting evidence, not as a main structural element. It doesn't support the diagnosis.

**4. Issues Listed, Not Grouped**
The "Issues" section presents a string of problems (inconsistent data, incorrect calculations, re-entry errors) without thematic organization. Minto demands that supporting points be consolidated into 2–3 key arguments. These issues should be grouped—e.g., by root cause or impact type—to form coherent supporting logic.

**5. Weak Opening**
"Since Period 5, Financial Analysis has been responsible..." opens with chronology and context, not the business problem. This delays the reader's understanding of why the memo exists.

**6. Vague Close**
The ending is a question, not a recommendation. The memo diagnoses but does not prescribe; it invites discussion rather than proposing action.

## What Must Change

- **Restructure opening**: Lead with the main message—that the fragmented process is unmanageable and requires redesign—before any background.
- **Condense process description**: Move the four production steps to supporting detail; they exist only to explain *why* the process is fragmented, not as a primary argument.
- **Consolidate issues into groups**: Reorganize the problems into 2–3 supporting arguments (e.g., "Data is entered multiple times with no single owner" and "No controls exist between production stages").
- **Add explicit recommendation**: State clearly what action Management should take (e.g., "We recommend consolidating production under one owner with a redesigned workflow").
- **Rewrite closing**: Replace the question with a direct call to action.
